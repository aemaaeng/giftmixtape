# 작업 방식

설계는 사람이, 구현은 Claude가, 검증은 같이 한다. 사람이 이해하지 못한 코드는 머지하지 않는다.

## 작업 단위

- 기능 하나당 브랜치 하나, PR 하나. 한 번에 여러 기능을 만들지 않는다
- 요청받은 범위만 바꾼다. 관련 없는 리팩터링이나 추가 기능은 제안만 한다
- 커밋과 push는 사람이 직접 한다. 커밋 메시지는 제안할 수 있다

## 설계가 필요할 때

- 데이터 구조, 폴더 구조, 핵심 인터페이스는 사람이 정한다
- `docs/architecture.md`나 `docs/conventions.md`에서 "미정"인 부분이 필요하면, 구현 전에 초안을 제안하고 확인받는다
- 확정된 결정은 해당 문서에 반영한다

## 완료 기준

작업을 끝냈다고 말하기 전에 아래를 모두 통과시킨다.

```bash
pnpm lint && pnpm typecheck && pnpm test
```

화면이나 흐름을 바꿨으면 `pnpm test:e2e`도 돌린다. 통과하지 못한 항목이 있으면 그대로 보고한다.

커밋할 때 husky가 lint-staged, 타입 체크, 단위 테스트를 다시 돌리고, PR에서는 GitHub Actions가 build와 e2e까지 돌린다.

## 기록

- 결정은 개인 노션 "믹스테이프 선물하기" 페이지의 결정 기록 DB에 질문 → 결정 → 이유로 남긴다
- 할 일은 같은 페이지의 할 일 DB에서 관리한다
